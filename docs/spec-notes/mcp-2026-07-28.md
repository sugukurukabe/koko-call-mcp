# MCP 2026-07-28 仕様読み取りと HTTP アダプタ実装メモ / MCP 2026-07-28 Notes & HTTP Adapter Scope / Catatan MCP 2026-07-28 & Cakupan Adapter HTTP

## 日本語

- **実SDKとアダプタの正確な境界**: JP Bids MCP v0.10.1 の実行時は `@modelcontextprotocol/sdk@1.32.2`（`2025-11-25` 系 v1 メンテナンスライン）を使用する。SDK 1.32.2 の `WebStandardStreamableHTTPServerTransport` 自体は `2025-11-25` までの版数しかネイティブ受理しないため、`src/transports/http.ts` に **`2026-07-28` ステートレス HTTP / `_meta` 境界アダプタ** を実装している。これは HTTP リクエスト契約の互換層であり、モジュラー v2 SDK（`@modelcontextprotocol/server@2.x`）への全面移行や `2026-07-28` 全機能の完全準拠を意味しない。
- **ステートレス契約の検査**: `MCP-Protocol-Version: 2026-07-28` または `params._meta["io.modelcontextprotocol/protocolVersion"] === "2026-07-28"` のリクエストでは、次を厳格に要求・検証する:
  1. JSON-RPC 単一オブジェクトであること（バッチ配列は `400 InvalidBatchRequest`）。
  2. `Mcp-Session-Id` ヘッダーおよび `initialize` / `notifications/initialized` メソッドを含まないこと（含まれる場合は `400 StatelessProtocolViolation`）。
  3. `MCP-Protocol-Version` ヘッダーと `params._meta["io.modelcontextprotocol/protocolVersion"]` の双方が存在し一致すること（欠落は `400 MissingRequiredHeader` / `400 MissingProtocolMetadata`、不一致は `400 HeaderMismatch`）。`io.modelcontextprotocol/clientInfo` および `io.modelcontextprotocol/clientCapabilities` が付与された場合は構造を検証する。
  4. `Mcp-Method` ヘッダーが必須であり JSON-RPC `method` と一致すること（欠落は `400 MissingRequiredHeader`、不一致は `400 HeaderMismatch`）。
  5. **メソッド別の `Mcp-Name` 検証**:
     - `tools/call`・`prompts/get`: `Mcp-Name` 必須、比較元は `params.name`。
     - `resources/read`・`resources/subscribe`・`resources/unsubscribe`: `Mcp-Name` 必須、比較元は `params.uri`。
     - 名前を持たないメソッド（`tools/list`・`resources/list`・`resources/templates/list`・`prompts/list`・`completion/complete`・`ping` 等）: `Mcp-Name` 不要（付与された場合は `400 HeaderMismatch`）。
  6. 認証通過後、SDK 1.32.2 内部処理向けに受信ヘッダーを `2025-11-25` へ橋渡しし、HTTP レスポンスには `MCP-Protocol-Version: 2026-07-28` を返す。
- **`2025-11-25` 旧クライアント互換**: `MCP-Protocol-Version: 2025-11-25`（または初期化時ヘッダー省略）では `Mcp-Method` / `Mcp-Name` は任意とする。ただし付与された場合は同じメソッド別比較元（`resources/read` は `params.uri`、`tools/call` / `prompts/get` は `params.name`）で一致検査を行う。
- **未実装の `2026-07-28` / ロードマップ項目**: `ttlMs` / `cacheScope`、`server/discover`、`io.modelcontextprotocol/tasks` 拡張（SDK 1.32.2 では `./experimental/tasks` のみ存在）、MRTR Elicitation、DPoP は未実装である。JP Bids MCP の検索・順位付け・エクスポートは短時間の同期 `tools/call` で完結するため、実験版 Tasks には依存しない。
- **Roots / Sampling / Logging 非推奨への対応**: `public_mvp` では Sampling を使用せず、外部文書抽出も既定で OFF（`JP_BIDS_DOCUMENT_EXTRACTION=off`）とする（ADR-0024）。OAuth は RFC 9207 の `iss` と RFC 6749 §5.1 の `Cache-Control: no-store` を付与済み。

## English

- **Exact boundary between SDK 1.32.2 and the HTTP adapter**: JP Bids MCP v0.10.1 runs on `@modelcontextprotocol/sdk@1.32.2` (the v1.x `2025-11-25` maintenance line). Because SDK 1.32.2's `WebStandardStreamableHTTPServerTransport` natively accepts protocol versions only up to `2025-11-25`, `src/transports/http.ts` implements an explicit **`2026-07-28` stateless HTTP / `_meta` boundary adapter**. This provides HTTP transport and request-contract interoperability without claiming migration to modular SDK v2 (`@modelcontextprotocol/server@2.x`) or full `2026-07-28` feature coverage.
- **Stateless contract enforcement**: Whenever `MCP-Protocol-Version: 2026-07-28` or `params._meta["io.modelcontextprotocol/protocolVersion"] === "2026-07-28"` is used, `src/transports/http.ts` enforces:
  1. Single JSON-RPC object body (batch arrays rejected with `400 InvalidBatchRequest`).
  2. No `Mcp-Session-Id` header and no `initialize` / `notifications/initialized` handshake (`400 StatelessProtocolViolation`).
  3. Both `MCP-Protocol-Version` header and `params._meta["io.modelcontextprotocol/protocolVersion"]` must be present and equal (`400 MissingRequiredHeader` / `400 MissingProtocolMetadata` / `400 HeaderMismatch`), plus shape checks on optional `io.modelcontextprotocol/clientInfo` and `io.modelcontextprotocol/clientCapabilities`.
  4. Mandatory `Mcp-Method` matching JSON-RPC `method` (`400 MissingRequiredHeader` / `400 HeaderMismatch`).
  5. **Method-aware `Mcp-Name` validation**:
     - `tools/call`, `prompts/get`: `Mcp-Name` required and compared against `params.name`.
     - `resources/read`, `resources/subscribe`, `resources/unsubscribe`: `Mcp-Name` required and compared against `params.uri`.
     - Unnamed methods (`tools/list`, `resources/list`, `resources/templates/list`, `prompts/list`, `completion/complete`, `ping`, etc.): `Mcp-Name` omitted (if sent, rejected with `400 HeaderMismatch`).
  6. After authentication, the adapter bridges the internal SDK header to `2025-11-25` and sets `MCP-Protocol-Version: 2026-07-28` on the HTTP response.
- **`2025-11-25` client compatibility**: Under `2025-11-25`, `Mcp-Method` and `Mcp-Name` remain optional; when supplied, they are validated using the same method-aware rules (`params.uri` for `resources/read`, `params.name` for `tools/call` and `prompts/get`).
- **Unimplemented `2026-07-28` / roadmap items**: `ttlMs`, `cacheScope`, `server/discover`, the `io.modelcontextprotocol/tasks` extension (only `./experimental/tasks` exists in SDK 1.32.2), MRTR elicitation, and DPoP are not implemented. All JP Bids workflows execute as short synchronous `tools/call` operations.
- **Deprecated primitives & OAuth hardening**: `public_mvp` never invokes Sampling and defaults `JP_BIDS_DOCUMENT_EXTRACTION=off` (ADR-0024). OAuth includes RFC 9207 `iss` and RFC 6749 §5.1 `Cache-Control: no-store`.

## Bahasa Indonesia

- **Batas tepat antara SDK 1.32.2 dan adapter HTTP**: JP Bids MCP v0.10.1 berjalan di atas `@modelcontextprotocol/sdk@1.32.2` (jalur pemeliharaan v1.x `2025-11-25`). Karena transport bawaan SDK 1.32.2 hanya menerima versi hingga `2025-11-25`, `src/transports/http.ts` menyediakan **adapter batas HTTP / `_meta` stateless `2026-07-28`**. Ini menyediakan kompatibilitas kontrak HTTP tanpa mengklaim migrasi penuh ke SDK v2 atau cakupan seluruh fitur `2026-07-28`.
- **Penegakan kontrak stateless `2026-07-28`**: Menolak batch JSON-RPC (`400 InvalidBatchRequest`), menolak `Mcp-Session-Id` serta `initialize` / `notifications/initialized` (`400 StatelessProtocolViolation`), mewajibkan kecocokan `MCP-Protocol-Version` dan `params._meta["io.modelcontextprotocol/protocolVersion"]`, mewajibkan `Mcp-Method`, serta memvalidasi `Mcp-Name` berdasarkan metode (`params.name` untuk `tools/call` & `prompts/get`; `params.uri` untuk `resources/read`).
- **Kompatibilitas `2025-11-25`**: Pada `2025-11-25`, `Mcp-Method` dan `Mcp-Name` tetap opsional namun divalidasi dengan aturan per-metode yang sama jika dikirim.
- **Fitur yang belum diimplementasikan**: `ttlMs`, `cacheScope`, `server/discover`, ekstensi `io.modelcontextprotocol/tasks`, MRTR elicitation, dan DPoP belum diimplementasikan.
